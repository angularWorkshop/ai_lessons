# Сообщение коммита

## Порядок работы

1. Прочитай diff целиком. Пойми, что меняется для поведения программы, а не какие строки поменялись.
2. Выбери type: `feat` — новая возможность, `fix` — исправление ошибки, `refactor` — поведение то же, код другой, `perf`, `docs`, `test` — меняются только тесты, `build` — зависимости и сборка, `chore` — всё остальное.
3. Выбери scope по списку модулей в `references/scopes.md`. Прочитай его: scope — не имя файла, а имя модуля из списка. Изменения в нескольких модулях — scope главного из них. Главного нет — сообщение без scope.
4. Subject: на английском, в повелительном наклонении, со строчной буквы, без точки в конце. Вся первая строка вместе с type и scope — не длиннее 72 символов.
5. Тело пиши только для `fix` и для ломающих изменений: пустая строка после subject, затем одна-две строки на английском — что было не так до коммита.
6. Ломающее изменение: `!` перед двоеточием, например `feat(agent)!: …`, и последняя строка `BREAKING CHANGE: <что сломается у вызывающего кода>`.

## Формат ответа

Только текст сообщения, готовый для `git commit -F -`: без кавычек, без ограждений ``` и без пояснений до или после.

## Пример

Diff меняет в `src/llm.ts` проверку `if (seconds)` на `if (Number.isFinite(seconds))`. Ответ:

```text
fix(llm): accept Retry-After: 0 as a valid delay

A zero value was treated as missing, so the client fell back to backoff.
```
