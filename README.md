# Итоговый проект: агент поддержки «Тетради»

**Тема 15.3 — Прогон eval-набора и отчёт.** Допиши `src/eval.ts` по шагам 1–3, прогони набор на настоящей модели, разбери провалы и сделай одну итерацию с замером до и после — шаг 4.

## Задача

«Тетрадь» — сервис заметок с синхронизацией: сайт, iPhone, Android, приложение для компьютера. Клиенты пишут в поддержку. Нужен агент, который на каждый вопрос делает одно из трёх:

- **отвечает по базе знаний** и ссылается на статьи, из которых взял факты;
- **честно отказывает**, если в базе ответа нет, — без выдуманных цен, сроков и функций;
- **передаёт вопрос специалисту**: заводит обращение (тикет) и называет клиенту его номер.

Один вопрос — один прогон. Истории диалога нет.

## Данные

- `data/kb/` — база знаний, статьи в Markdown. Путь статьи от `data/kb` — её идентификатор: `billing/refund.md`.
- `data/tickets/` — обращения, по JSON-файлу на каждое: `T-1042.json`. Формат — как у лежащих там примеров.

## Контракт

`src/support-agent.ts`:

```ts
createSupportAgent(options: {
  provider: Provider;   // complete(messages, options) → ChatResult, как в курсе
  dataDir: string;      // папка с kb/ и tickets/
  maxSteps?: number;    // запросов к модели на вопрос, по умолчанию 6
  onTool?: (event: { call: ToolCall; result: ToolResult }) => void;
}): { run(question: string): Promise<SupportResult> }

interface SupportResult {
  answer: string;       // что увидит клиент
  draft: string;        // что написала модель до проверок harness
  sources: string[];    // статьи, на которые ответ ссылается и которые агент прочитал
  ticket?: Ticket;      // обращение, если оно заведено
  stopReason: 'done' | 'max_steps' | 'error';
  steps: number;        // сколько раз агент спросил модель
  usage: { input: number; output: number };
}
```

`src/llm.ts` экспортирует `loadConfig(env)` и `llmProvider(config)` — клиент к модели курса из `.env`.

`run` не бросает исключений: если модель недоступна, `stopReason: 'error'`.

## Инструменты, которые видит модель

- `search_kb({ query })` — поиск статей по словам. Ответ — до 5 статей: путь, заголовок, строка с найденными словами.
- `read_article({ path })` — статья целиком. Путь — только внутри `data/kb` и только `.md`.
- `create_ticket({ summary, priority })` — завести обращение. `priority`: `urgent` — чужой человек получил доступ к аккаунту, иначе `normal`. Номер выбирает harness, вопрос клиента кладёт в тикет дословно. Одно обращение на вопрос.

Ошибка в инструменте — не исключение, а текст для модели, начинающийся с `Ошибка`.

## Правила harness

1. Ссылка на статью в ответе — путь `.md`, например `[billing/refund.md]`. В `sources` попадают только статьи, которые агент **прочитал в этом прогоне**.
2. Ответ без единого подтверждённого источника и без обращения клиенту не уходит: вместо него — честный отказ. Черновик модели остаётся в `draft`.
3. Если заведено обращение, номер обращения есть в ответе — даже если модель его не назвала.
4. Не больше `maxSteps` запросов к модели. Последний — без новых вызовов (`toolChoice: 'none'`); вызовы, которые модель всё же сделала, не исполняются.

## Eval-набор

`evals/cases.json` — вопросы клиентов и что агент должен сделать:

```json
{
  "id": "refund-5-days",
  "question": "Оплатил Плюс на сайте 5 дней назад и передумал. Можно ещё вернуть деньги и до какого срока?",
  "expect": "answer",
  "sources": ["billing/refund.md"],
  "mustInclude": ["14"]
}
```

- `expect: "answer"` — ответ со ссылкой хотя бы на одну статью из `sources` и со всеми фактами из `mustInclude` (пробелы и регистр не важны);
- `expect: "refuse"` — ни источников, ни обращения;
- `expect: "ticket"` — обращение заведено, у него приоритет `priority`.

## Команды

- `npm run start:dev` — проверка, перезапускается при каждом сохранении. Готово — `ASSIGNMENT STATUS: COMPLETED`.
- `npm test`, `npm run typecheck`.
- `npm run ask -- "вопрос"` — один вопрос агенту на настоящей модели.
- `npm run eval` — весь eval-набор на настоящей модели, `npm run eval -- hacked weather` — только эти кейсы. Отчёт каждого прогона — в `evals/runs/`, новый сравнивается с прошлым.
Модель уже подключена: платформа сама кладёт в проект `.env` с адресом, ключом и моделью.
